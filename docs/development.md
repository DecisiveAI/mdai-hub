# Development

Development setup for SmartHub starts with the `mdai-hub` chart. This page covers prerequisites, chart dependency updates, direct Helm installation, and the cert-manager configuration path.

## Reference

The SmartHub chart source is available in the `mdai-hub` repository:

- [MyDecisive/mdai-hub README](https://github.com/MyDecisive/mdai-hub/tree/main#prerequisites)

## Prerequisites

Before installing, developing, or validating the SmartHub chart directly, confirm:

- Kubernetes `1.24+`.
- Helm `3.9+`.
- cert-manager when using the default webhook certificate path.

cert-manager is optional only when the chart values are changed to use autogenerated webhook certificates instead. See [Disable cert-manager](#disable-cert-manager).

## Chart Dependency Update

After initial checkout, switching branches, or modifying `Chart.yaml`, update chart dependencies from the `mdai-hub` repository root:

```shell
helm dependency update . --repository-config /dev/null
```

This keeps the local chart dependency lock and downloaded charts aligned with the current chart metadata before install, lint, packaging, or validation work.

## Direct Helm Install

Install or upgrade the SmartHub chart into a Kubernetes cluster:

```shell
helm install my-mdai-hub oci://ghcr.io/mydecisive/charts/mdai-hub --version 0.x.x
```
See all [available tags](https://github.com/MyDecisive/mdai-hub/tags)

Use `grafana-values.yaml` when you want to deploy Grafana with MDAI dashboards to the cluster.

## Disable cert-manager

When cert-manager is not available, update values so the OpenTelemetry Operator and MDAI Operator admission webhooks generate certificates automatically.

Set OpenTelemetry Operator webhook certificate values:

```yaml
opentelemetry-operator:
  enabled: true
  admissionWebhooks:
    certManager:
      enabled: false
    autoGenerateCert:
      enabled: true
      recreate: true
      certPeriodDays: 365
```

Set MDAI Operator webhook certificate values:

```yaml
mdai-operator:
  enabled: true
  admissionWebhooks:
    certManager:
      enabled: false
      issuerRef: {}
      certificateAnnotations: {}
      issuerAnnotations: {}
      duration: ""
      renewBefore: ""
    autoGenerateCert:
      enabled: true
      recreate: true
      certPeriodDays: 365
```

## Validation

After dependency updates or a direct install, validate the target namespace:

```shell
kubectl get pods --namespace mdai
```

Expected result: SmartHub workloads are running or progressing to ready. If pods do not become ready, check chart dependency updates, image pull access, webhook certificate configuration, Kubernetes events, and pod logs.
